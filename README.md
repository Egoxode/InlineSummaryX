# InlineSummaryX

SillyTavern extension. Select a range of chat messages, replace it with one summary, keep the originals attached to that summary, restore them later if you need to.

Fork of [Kristyku/InlineSummary](https://github.com/Kristyku/InlineSummary).

Version **1.3.18** (based on upstream 1.2.2) ([changelog](changelog.md))

## AI Disclaimer

This fork was edited with an AI assistant. Read the code before you rely on it. Summaries the extension writes into chat are generated by whatever model you have selected in SillyTavern — they can be incomplete or wrong. Keep the originals attached to the summary if you may need the source text later.

## Install

1. In SillyTavern open **Extensions → Install Extension**.
2. Paste:

```
https://github.com/Egoxode/InlineSummaryX
```

3. Reload the page.

Remove the original KristyKu copy first if it is already installed. Two copies will fight over the same chat buttons.

The install folder may be named `InlineSummaryX`. Settings still live under the `InlineSummary` key, so old presets and chats keep working.

## Usage

### Make a summary

1. On the first message of the range, click **Select Summary Start**.
2. On the last message, click **Select Summary End**.
3. Inside the highlighted range three extra actions appear: **Summarise (AI)**, **Summarise (Manual)**, **Clear Selection**.
4. **Summarise (AI)** immediately replaces the range with a `Generating...` message. The originals are stored on that message. When the model returns, its text is written into the same message.
5. **Summarise (Manual)** inserts an editable placeholder instead of calling the model.

If generation is cancelled or fails, the `Generating...` message stays and the error (or a cancel note) is written into it. Originals are still inside the message — use **Restore Original** to unpack them. Turn on **Restore originals if summary generation is cancelled or fails** if you want the range unpacked automatically instead.

If you switch to another chat while a summary is generating, the result is discarded and nothing is written into the other chat. The originals stay in the `Generating...` message of the original chat.

### Work with an existing summary

Every summary has an **Original Messages** header.

- Click the header (not the buttons) to expand or collapse the stored originals. Token counts are estimates, for example: `Original Messages: 8/8 used | ~1540 tokens | Summary: ~212 tokens`. While the summary is still generating, the last number is `…`.
- **Restore Original and Delete Summary** puts the originals back and removes the summary.
- **Re-Summarise (AI)** generates a new summary from the stored originals. If it is cancelled or fails, the existing summary is kept unchanged.

Summaries are normal chat messages: they go into later prompts, they can be edited, and they can be summarised again. A nested summary uses the summary text, not the hidden originals.

## Slash commands

| Command | What it does |
| :--- | :--- |
| `/ils 1 10` | Summarise messages 1–10 with AI (inclusive) |
| `/ils manual=true 1 10` | Insert a manual placeholder for 1–10 |
| `/ils-restore 5` | Unpack the 5 newest summaries |
| `/ils-restore all` | Unpack every summary in this chat, including nested ones |

Aliases: `/ils-sum`, `/ils-summarise`, `/ils-summarize` for `/ils`; `/ils-undo`, `/ils-back` for `/ils-restore`. `*` is the same as `all`.

While a summary is being generated, `/ils` and `/ils-restore` do nothing and show "Another summary operation is running". Run them again when it has finished.

## Settings

Open **Extensions → InlineSummaryX**.

### Prompt

| Setting | Meaning |
| :--- | :--- |
| Setting Presets | Named presets; new / delete / import / export / reset. New and import never overwrite an existing preset (import adds a number to the name) |
| Summary Prompt Start | The full instruction sent to the model. Put extra rules here |
| Historical Context Size | How many messages *before* the range to include as background. `-1` fills the context window, `0` includes none |
| Historical Context Start / End Marker | Wrappers around that background block |
| Response Token Limit | Max summary length in tokens. `0` uses the current SillyTavern preset |

The prompt is built in this order: start prompt + start marker → historical messages → end marker → messages in the range. Hidden and system messages are skipped. With **Enable Multi Message Prompt** the pieces are sent as separate user/assistant turns with speaker names; otherwise they are joined into one user message.

**Default prompt.** The built-in prompt (`defaults.json`) writes a structured, information-dense summary in English: the current state of the whole story in sections (beginning, current scene, recent events, `{{char}}`, `{{user}}`, side characters, relationships, character development, secrets and knowledge, open threads, important facts, continuity details). SillyTavern replaces `{{char}}` and `{{user}}` with the names.
- It rebuilds the whole story every time, so select from the first message, or from the previous summary through the newest messages. A range from the middle of the chat repeats what is still above it.
- It refers to the default markers `<Historical_Context>` / `</Historical_Context>`. If you change the markers, change them in the prompt too.
- Summary length is set by **Response Token Limit** (or the SillyTavern preset when it is `0`). For long stories, raise it: the limit is reserved in the context, so the context must hold the limit plus the messages.
- It is used for a new installation, a new Setting Preset, and **Reset to Default**. A prompt you have already saved is not replaced.

### Connection

| Setting | Meaning |
| :--- | :--- |
| Use specified Connection Profile | Switch API profile only while summarising. The chat needs a connection profile of its own (Connection Profiles), so it can be switched back; without one the summary does not start |
| Use specified API Preset | Switch generation preset only while summarising (the preset chosen for the API in use; with a different Connection Profile, the API of that profile). Afterwards the preset is restored first, then the profile. Stays ticked if no preset is chosen yet (`<None>`, nothing is switched); it is unticked only if the chosen preset no longer exists |

Unsaved edits to the current profile or preset are discarded when the extension swaps them.

### Behaviour

| Setting | Meaning |
| :--- | :--- |
| Auto Scroll to summarised message | Jump to the summary after generation |
| Restore originals if summary generation is cancelled or fails | Off (default): keep the placeholder and write the error into it. On: unpack the original messages |
| Enable Regex when summarising messages | Run SillyTavern Regex on source messages before the request |
| Enable Regex on final summary | Run SillyTavern Regex on the finished summary, like on a normal AI reply (AI Output and Reasoning scripts; "Run On Edit" is not needed) |
| Enable Multi Message Prompt | Send the prompt as separate turns instead of one blob |
| Summary message sender name | Author on the summary: User / Character / Custom |
| Restore legacy summary messages | One-time repair for chats created before upstream v1.2 |
| Restore all originals in this chat | Same as `/ils-restore all` |

## Uninstall

Summaries are normal chat messages. If you remove the extension without unpacking them, later chats still show the summary text and the originals stay buried in the chat file with no UI to restore them.

Before uninstalling, open **Settings → Misc Settings** and press **Unpack summaries in all chats**. It unpacks the open chat and rewrites every character and group chat file on disk that still contains stored originals, including chats that are not open. Wait for the result message: it tells how many chat files were rewritten, and whether any could not be processed (then press the button again).

Deleting the extension or using **Clean extension data** also tries to do this, but SillyTavern reloads the page about 5 seconds after calling the extension. With many chats (about 1000 in tests) that pass is cut off and some chats keep their summaries, so use the button first.

## Notes

- JSON export keeps the stored originals. Plain-text export keeps only the summary text.
- Swipes on a summary keep the stored originals on the message. The Original Messages header stays after a swipe.
- If only the last N messages are loaded, Start on the first *visible* message is not chat index 0. Load older messages first, or use `/ils 0 149`.
- The Document chat style hides older message-action buttons, so Start/End are missing there. Bubbles and Flat work.
- Token counts use SillyTavern's counter and may not match the live model.
- A range needs at least two messages. This fork is based on upstream 1.2.2 and does not include upstream 1.2.3 (alternative preset slots, single-message summaries).

## What this fork changes

- `/ils-restore all` and a settings button that fully expands the current chat.
- On extension delete / clean data, the open chat is unpacked and other saved chats are rewritten when possible.
- Mid prompt, end prompt, and content start/end markers removed. Instructions live in the main prompt.
- `Generating...` is inserted immediately; the model output (or the error text) is written into that same message.
- Optional restore-on-abort checkbox.
- Original Messages header also shows an estimate of the summary's own tokens.
- Speaker names are included in the summary prompt.
- Settings load from the installed folder URL.
- After a summary is inserted, the chat is fully reloaded and older messages are loaded until the summary is in the DOM. This fixes long chats that only show the last N messages.
- Fixes from the fork: token display after reload, Original Messages token path after v1.2, legacy-recovery checkbox actually saves, rollback if the first save fails, profile-restore error text.
- Fixes in 1.3.9: summaries work again with streaming OpenAI-compatible APIs (the request was never sent); the temporary token limit is always restored; chat switch during generation is safe; a failed Re-Summarise keeps the old summary; the operation lock is always released after errors; old chats without swipe data load without errors; settings presets are no longer overwritten by New / Import, and a bad import shows an error.
- Fix in 1.3.10: clicking the Generating toast now cancels at once with every API, like Stop. Before, with streaming off it waited until the model finished.
- Fix in 1.3.11: a backend error no longer leaves an "Uncaught (in promise)" error in the browser console.
- Fix in 1.3.12: if something fails after the summary request is sent, the request is stopped instead of running to the end in the backend.
- Fixes in 1.3.13: if the chat cannot be saved when a summary starts, the request is stopped at once instead of waiting for the whole response (and no wrong "chat was changed" warning); the temporary token limit is restored after such failures.
- Added in 1.3.14: **Unpack summaries in all chats** button (Settings → Misc) for a complete unpack before uninstalling.
- Fixes in 1.3.17: no summary with a different connection profile while the chat has no profile of its own (the summary profile used to stay active); `{{char}}` / `{{user}}` in the prompt are replaced with Chat Completion streaming too; the API Preset list starts with `<None>`.
- Fixes in 1.3.18: `/ils` while a summary is generating no longer moves that summary (it could overwrite another summary); `/ils` and `/ils-restore` then say that another operation is running; a manual summary locks sending like an AI summary; in the expanded originals your messages show your persona avatar.
